# Модуль управления каталогом товаров

Учебный проект курсовой работы МФЮА на тему «Разработка модуля управления каталогом товаров для интернет-магазина».

Стек: Python 3.12, FastAPI, Jinja2, SQLAlchemy и SQLite. Локальная система разработки и демонстрации — macOS. Реализованы база и API каталога: создание, просмотр, изменение и удаление товаров и категорий, поиск, фильтры, сортировка и пагинация. HTML-интерфейс появится на этапе 6.

## Подготовка macOS

Откройте приложение «Терминал» и проверьте Python и Git:

```bash
python3.12 --version
git --version
```

Нужен Python 3.12.x. Если Python отсутствует и Homebrew уже установлен:

```bash
brew install python@3.12
```

Если Homebrew не установлен, его официальная инструкция находится на [brew.sh](https://brew.sh/). После установки выполните команду выше и снова проверьте `python3.12 --version`. Если macOS предложит установить инструменты командной строки при первом запуске Git, завершите их установку и повторите проверку.

## Установка и первый запуск

Все следующие команды выполняются из корня репозитория — папки с этим README:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python --version
python -m pip install -r requirements-dev.txt
python -m pip check
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Ожидаемая версия после активации — Python 3.12.x. Виртуальное окружение `.venv` отделяет зависимости проекта от остальных программ. `requirements-dev.txt` подключает `requirements.txt` и добавляет инструменты будущих тестов. Все версии пакетов, включая транзитивные зависимости, зафиксированы. Для одного запуска приложения без инструментов разработки достаточно `python -m pip install -r requirements.txt`.

Uvicorn занимает текущий терминал; это нормально. Дождитесь сообщения `Application startup complete`. Параметр `--reload` перезапускает сервер при изменении Python-файлов. Для остановки нажмите Control+C.

## Проверка на своем Mac

В адресную строку браузера введите `http://127.0.0.1:8000/`. Должен появиться ответ:

```json
{"message":"Модуль управления каталогом товаров"}
```

По адресу `http://127.0.0.1:8000/health` ожидается:

```json
{"status":"ok"}
```

Для документации введите `http://127.0.0.1:8000/docs`. Доступны группы «Товары» и «Категории», а также `GET /` и `GET /health`. Можно раскрыть операцию, нажать `Try it out`, затем `Execute`. Примеры создания и фильтрации приведены в [этапе 5](docs/STAGE_5.md). Файлы интерфейса Swagger загружаются из CDN и требуют доступа в интернет; сами JSON-маршруты работают локально.

Проверить ответ сервера также можно во втором окне терминала:

```bash
curl --fail --silent --show-error http://127.0.0.1:8000/health
```

На этом этапе главная страница возвращает JSON. Страницы каталога и формы будут реализованы на этапе 6. Главная страница позже станет переходом к каталогу по проекту.

## Повторный запуск

Откройте терминал в папке проекта:

```bash
source .venv/bin/activate
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Заново создавать окружение и устанавливать пакеты при каждом запуске не нужно. После обновления файлов зависимостей повторите `python -m pip install -r requirements-dev.txt`. Чтобы выйти из окружения после остановки сервера, выполните `deactivate`.

Если порт 8000 уже занят другой программой, используйте `--port 8001` и тот же порт в браузере. Ошибка `No module named app` обычно означает запуск вне корня репозитория; убедитесь, что в текущей папке видны `app/` и `README.md`.

## Облачная среда

Рабочая папка — `/workspace/kyyyyyrsach`. Здесь также используется `.venv` с Python 3.12. Подготовка и проверка зависимостей:

```bash
cd /workspace/kyyyyyrsach
python3.12 -m venv .venv
.venv/bin/python -m pip install --no-input --disable-pip-version-check --cache-dir /tmp/kyyyyyrsach-pip-cache -r requirements-dev.txt
.venv/bin/python -m pip --cache-dir /tmp/kyyyyyrsach-pip-cache check
```

Запуск без автоматической перезагрузки:

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В облаке адрес используется для внутренних запросов проверки; он не является опубликованным сайтом. Виртуальное окружение, кэши и рабочая база не отправляются в GitHub.

## База данных и проверки

При запуске сервера автоматически создается `data/catalog.db` с таблицами `categories` и `products`. Путь привязан к папке проекта. Повторный запуск сохраняет записи. База и ее служебные файлы исключены из Git; на другом компьютере создается пустая схема. Существующие таблицы автоматически не мигрируют при изменении моделей.

Проверки базы выполняются на отдельных временных файлах:

```bash
python -m pytest -q
```

В облачной среде пройдены 116 тестов: 35 проверок базы и 81 проверка API. Дополнительно выполнены 29 HTTP-запросов через отдельный сервер с перезапуском на временной базе. Рабочие данные не изменились. Есть одно предупреждение Starlette об устаревающем режиме HTTPX в тестовом клиенте; оно не подавлено, проверки проходят. Подробности — в [описании этапа 5](docs/STAGE_5.md).

## Работа с API

Создайте категорию через POST `/api/categories`, затем товар через POST `/api/products`, указав полученный `category_id`. Цена передается строкой в рублях, например `"49.90"`, а количество — целым JSON-числом. PUT товара требует все обязательные поля. DELETE занятой категории возвращает 409; после переноса или удаления ее товаров пустую категорию можно удалить.

GET `/api/products` принимает `q`, `category_id`, `min_price`, `max_price`, `in_stock`, `sort`, `page`. Выдача содержит `items`, `total`, `page`, `page_size`; размер страницы — 10. Поиск работает с русским текстом без учета регистра, ценовые границы включительны. Варианты сортировки: `name_asc`, `name_desc`, `price_asc`, `price_desc`, `updated_desc`. Полный пример JSON и порядок демонстрации — в [этапе 5](docs/STAGE_5.md).

## Состояние

Окружение, база и API проверены в облачной Linux-среде. Инструкция для macOS подготовлена; выполнение на компьютере студента ожидает подтверждения. Веб-страницы и формы пока не реализованы. Следующий этап — интерфейс на Jinja2 после отдельного согласования.

Через API реализованы управление товарами и категориями, поиск, фильтрация, сортировка и учет текущих остатков. Демонстрационный ассортимент — канцелярские товары.
