# Модуль управления каталогом товаров

Курсовой проект МФЮА на тему «Разработка модуля управления каталогом товаров для интернет-магазина».

Приложение хранит товары и категории в SQLite. Через веб-страницы и JSON API можно добавлять, просматривать, изменять и удалять записи. Список поддерживает поиск по названию, совместные фильтры категории, цены и наличия, сортировку и страницы по 10 товаров. Категорию с товарами удалить нельзя.

Автор: Чемоданов Никита Сергеевич, группа 23ИПо8381 (ИПо-41), 4-й курс. Руководитель: Колпащиков Кирилл Александрович. Киров, 2026.

## Для кого эта инструкция

README предназначен студенту и преподавателю, которому нужно установить, запустить и проверить программу. Пояснительная записка, презентация и техническая документация находятся в `docs/` и перечислены в конце страницы.

Стек: Python 3.12, FastAPI, Jinja2, SQLAlchemy, SQLite и Uvicorn. Основные формы работают без JavaScript; скрипт переводит даты в местное время браузера. Сервер рассчитан на локальную демонстрацию одним менеджером. Авторизация, заказы, оплата, доставка и история складских движений не реализованы.

## Установка на macOS

Проверьте Python и Git:

```bash
python3.12 --version
git --version
```

Нужен Python 3.12.x. Если Homebrew уже установлен, Python можно установить командой `brew install python@3.12`. Инструкция самого Homebrew находится на [brew.sh](https://brew.sh/).

При первом получении проекта:

```bash
git clone https://github.com/Koryza/kyyyyyrsach.git
cd kyyyyyrsach
```

Если копия уже есть, откройте её папку. Обновление выполняется командой `git pull --ff-only`; перед ним сохраните свои изменения.

Из корня репозитория создайте окружение и установите закреплённые зависимости:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pip check
```

После активации `python --version` должен показывать 3.12.x. Для запуска без тестовых инструментов достаточно `requirements.txt`.

## Запуск и проверка

Из корня проекта в активированном окружении:

```bash
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Дождитесь `Application startup complete`. Сервер занимает терминал до остановки Control+C. На своём компьютере откройте `http://127.0.0.1:8000/`: главный адрес перенаправляет на `/products`. У новой базы список пустой. Сначала создайте категорию, затем товар.

Во втором терминале из папки проекта выполните проверку страниц, API и структуры SQLite:

```bash
source .venv/bin/activate
python -m scripts.check_ready
```

Проверка только читает данные. Отдельно ответ `/health` должен быть `{"status":"ok"}`:

```bash
curl --fail --silent --show-error http://127.0.0.1:8000/health
```

JSON API находится под префиксом `/api`, документация — по `/docs`. Swagger загружает файлы из CDN; страницы каталога используют локальные CSS и JavaScript.

Если порт 8000 занят, выберите `--port 8001` и используйте этот порт в браузере. Штатная команда `scripts.check_ready` проверяет порт 8000. Ошибка `No module named app` обычно означает запуск вне корня репозитория.

При повторном запуске достаточно активировать `.venv` и запустить Uvicorn. После изменения файлов зависимостей повторите установку пакетов.

## База и демонстрационные данные

При запуске создаётся `data/catalog.db` с таблицами `categories` и `products`. Повторный запуск сохраняет записи. База, резервные копии, окружение и кэши исключены из Git. `create_all()` создаёт отсутствующие таблицы, но не мигрирует существующую схему.

Для заполнения примерами:

```bash
python -m scripts.seed_demo
```

Команда добавляет 1200 синтетических товаров в 12 категориях. Перед записью в существующую базу сохраняется резервная копия; занятые артикулы пропускаются. Цены и остатки условные. Поведение повторной загрузки описано в [DEMO_DATA.md](docs/DEMO_DATA.md).

## Тесты

```bash
python -m pytest -q
```

Тесты используют отдельные временные SQLite-файлы. При проверке в облаке 22.10.2026 пройдены 154 теста: 35 базы, 81 API, 31 HTML и 7 загрузчика. Получено одно предупреждение Starlette об устаревающем использовании HTTPX в TestClient.

Протоколы браузерных проверок от 21.10.2026 содержат 14 сценариев интерфейса и 6 сценариев каталога из 1200 товаров. Условия воспроизведения — в [TESTING.md](docs/TESTING.md) и [DEMO_DATA.md](docs/DEMO_DATA.md).
