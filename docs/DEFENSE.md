## Основа выступления

Меня зовут Чемоданов Никита Сергеевич, группа ИПо-41. Моя работа посвящена модулю управления каталогом товаров интернет-магазина. В приложении менеджер добавляет товары и категории, меняет цены и остатки, ищет позиции и применяет фильтры. Для демонстрации выбран учебный каталог канцелярских товаров.

В проекте используются Python, FastAPI, SQLAlchemy, SQLite и Jinja2. FastAPI принимает запросы, SQLAlchemy выполняет операции с базой, а Jinja2 формирует HTML-страницы. SQLite позволяет запускать демонстрацию без отдельного сервера базы. Интерфейс работает с обычными формами; JavaScript нужен только для отображения дат в местном часовом поясе.

В базе есть две таблицы: категории и товары. Один товар относится к одной категории. Цена хранится в копейках. Для количества принимаются целые числа, начиная с нуля. Артикул уникален. Категория с товарами защищена от удаления. Сервер проверяет запрос перед записью. Ограничения базы также запрещают недопустимые значения и нарушенные связи.

Сейчас я покажу создание товара, поиск с несколькими фильтрами, редактирование остатка и реакцию на неправильную цену. Если ввод некорректен, форма сохраняет заполненные поля. Удаление товара требует подтверждения, а попытка удалить занятую категорию получает понятное объяснение.

Обработчики JSON API и веб-страниц вызывают функции из catalog.py. В обоих случаях одинаково проверяются артикул, категория и числовые значения. После успешного POST браузер перенаправляется на карточку или список. Это отделяет сохранение от следующего просмотра страницы.

Проверка включает 154 автоматических теста базы, API, HTML и загрузчика примеров. Дополнительно пройдены 14 основных сценариев в Chromium и 6 сценариев большого каталога. Автоматические тесты используют временные базы. Для демонстрации подготовлены 1200 товаров. Перед загрузкой в существующую базу создаётся резервная копия. Найденное переполнение мобильной страницы исправлено и проверено повторно.

Модуль готов к локальной демонстрации операций с каталогом. Остаток редактируется вручную. Для работы нескольких менеджеров потребуются авторизация, история изменений и проверка одновременной записи.

На репетиции проверьте длительность по таймеру и подготовьте объяснение каждого показанного действия. В протоколах есть результаты Chromium; замеров скорости и внедрения в организации нет.

## Демонстрация без изменения рабочего каталога

1. Открыть терминал в корне репозитория, активировать `.venv` и запустить `python -m scripts.check_server`. Он создаёт отдельную временную базу на время процесса.
2. Открыть в браузере `http://127.0.0.1:8001/`. Этот адрес относится к локальной демонстрации на своём Mac.
3. Создать категорию «Письменные принадлежности».
4. Добавить «Ручка синяя», артикул `DEMO-PEN-001`, цену `49,90`, остаток `20`. Открывается карточка.
5. Вернуться в список. Ввести `РУЧКА`, выбрать категорию, цену от `40` до `60`, «Только в наличии» и «Сначала дешевле»; нажать «Применить».
6. Открыть форму редактирования, ввести цену `1.234` и сохранить. Показать сообщение и сохранённые поля; затем исправить цену на `54,90`, остаток на `0` и сохранить.
7. При прежнем фильтре наличия товар исчезает; после сброса фильтра он снова виден с остатком ноль.
8. Открыть удаление занятой категории. Показать объяснение и ссылку на товары.
9. Открыть удаление товара, сначала отменить, затем подтвердить. Удалить пустую категорию.
10. Остановить тестовый сервер Control+C. Его временная база удаляется; обычный каталог на порту 8000 не затронут.

Если порт 8001 занят, сначала выяснить, каким процессом, и остановить свой предыдущий тестовый сервер. Для демонстрации сохранить готовые реальные снимки из `docs/figures/` как запасной материал. Если демонстрация не запустится, покажите сохранённые снимки и укажите дату тестового прогона.

## Вопросы и опорные ответы

| Вопрос | Что объяснить |
|---|---|
| Почему SQLite? | Локальная демонстрация и простая установка. Отдельный процесс сервера базы не нужен. Многопользовательская нагрузка не измерена. |
| Почему цена не float? | В базе лежат целые копейки; строка рублей разбирается через Decimal, лишняя точность отклоняется. |
| Как учитывается остаток? | Хранится текущее количество единиц товара. Приход и списание отдельными операциями не записываются. |
| Зачем два способа работы — HTML и API? | Один удобен менеджеру, другой возвращает структурированные данные. Они используют одинаковые правила в catalog.py. |
| Можно ли обойти проверку браузера? | Да, поэтому сервер проверяет данные заново, а база содержит ограничения. |
| Что произойдёт при повторном артикуле? | Ответ 409; введённые данные формы остаются, конфликтная запись не сохраняется. При конфликте записи транзакция откатывается. |
| Почему нельзя удалить занятую категорию? | Товар должен ссылаться на существующую категорию; правило проверяет приложение и внешний ключ RESTRICT. |
| Как работает поиск по-русски? | Хранится нормализованное имя: NFKC, strip, casefold. Искомая строка преобразуется так же; `%` и `_` ищутся буквально. |
| Что означает «В наличии»? | Количество строго больше нуля. Нулевая цена допустима и не определяет наличие. |
| Что такое пагинация? | Запрос считает общее число результатов и выбирает до 10 записей с нужным смещением; ссылки сохраняют фильтры. |
| Почему после POST ответ 303? | Браузер получает карточку отдельным GET; обновление этой страницы не повторяет отправку формы. |
| Сохраняется ли база после остановки? | Обычная база data/catalog.db сохраняется. Специальный тестовый сервер сознательно использует временный файл. |
| Есть ли миграции? | Нет. create_all создаёт отсутствующие таблицы, но не изменяет существующую схему. |
| Как доказана работоспособность? | Тестами pytest и сценариями Chromium. Команды и отчёты сохранены в репозитории; условия проверки перечислены в TESTING.md. |
| Что делает JavaScript? | Меняет отображение дат на часовой пояс браузера; формы, поиск и удаление работают без него. |

## Что уметь показать в коде

- Проследить один запрос от `app/routers/pages.py` через `ProductWrite` в `app/catalog.py` и модель Product.
- Показать `price_to_kopecks`, `list_products`, обработку IntegrityError и `rollback`.
- Объяснить `get_db`, жизненный цикл сессии и путь к `data/catalog.db`.
- Найти внешний ключ, ограничения уникальности, обработку формы и шаблон ошибки.
- Запустить `python -m pytest -q` и объяснить, почему тесты не используют рабочую базу.
