# Проверка приложения

## Автоматические тесты

Из корня репозитория после установки `requirements-dev.txt`:

```bash
.venv/bin/python -m pytest -q
```

В [протоколе от 09.11.2026](defense/figures/product-testing/automated-tests.xml) пройдены 154 теста, проваленных нет. Протокол от 29.10.2026 сохранён в материалах записки. После удаления декоративных значков 22.10.2026 отдельно повторно пройден 31 HTML-тест. Получено одно предупреждение Starlette об устаревающем использовании HTTPX в TestClient; зависимости сохранены.

| Группа | Число тестов | Что проверяется |
|---|---:|---|
| База данных | 35 | Файловое хранение, повторная инициализация, связи, ограничения, даты |
| JSON API | 81 | Операции, коды ответа, строгие типы, ошибки, поиск, фильтры и пагинация |
| HTML | 31 | Формы, сохранение ввода, перенаправления, экранирование и удаление |
| Загрузчик | 7 | Повторный запуск, сохранение своих записей, транзакционный откат и резервная копия |

Каждый тест получает отдельный временный SQLite-файл. Ошибка проверяется по ответу и состоянию данных: например, после отклонённого обновления запись должна совпадать с прежней. Рабочая `data/catalog.db` для тестовых записей не используется.

## Проверка запущенного сервера

В первом терминале из корня:

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале из той же папки:

```bash
.venv/bin/python -m scripts.check_ready
```

Команда только читает данные. Она проверяет HTML-страницы и формы, CSS/JavaScript, ответ health, списки API, десять операций OpenAPI, таблицы SQLite и включённые внешние ключи. Ожидается код завершения 0.

Один ответ `{"status":"ok"}` по `/health` подтверждает доступность обработчика, но не заменяет проверку схемы и операций каталога. `scripts.check_ready` рассчитан на порт 8000.

## Ручной сценарий API

Документация запущенного сервера доступна по `/docs`. Для проверки используйте отдельные демонстрационные записи:

1. Создайте категорию через POST `/api/categories`; сохраните возвращённый `id`.
2. Создайте товар через POST `/api/products`, указав категорию, название, уникальный артикул, цену `"49.90"` и целый остаток `20`. Ожидается 201.
3. Выполните GET `/api/products` с поиском `РУЧКА`, выбранной категорией и наличием. Проверьте состав `items` и `total`.
4. Попытайтесь удалить занятую категорию. Ожидается 409; товар и категория должны сохраниться.
5. Измените товар через PUT, передав все обязательные поля; прочитайте его повторно через GET.
6. Удалите демонстрационный товар, затем освободившуюся категорию. Ожидается 204 без тела ответа.

При разработке API отдельно выполнены 29 HTTP-проверок с перезапуском процесса на временной базе. Они учитываются отдельно от pytest и не прибавляются к числу 154.

## Браузерные сценарии

Исторический прогон 21.10.2026: 14 сценариев в Chromium на экранах 1440 × 1000 и 390 × 844. Проверены создание и изменение товаров, ошибочная цена с сохранением ввода, фильтры, переходы страниц, запрет удаления занятой категории, подтверждение и отмена удаления, форма без JavaScript.

После загрузки демонстрационного каталога выполнены ещё 6 сценариев: количество товаров API, пагинация, последняя страница, совместные фильтры, счётчики категорий и мобильная ширина. Отчёты сохранены в [browser-report.json](figures/browser-report.json) и [large-catalog/report.json](figures/large-catalog/report.json).

09.11.2026 для расширенной презентации повторно пройдены 14 основных сценариев Chromium. В отчёте подробно записаны шесть проверок: создание товара, отказ при ошибочной цене, изменение цены и остатка, запрет удаления занятой категории, отмена и подтверждение удаления товара. Эти шесть входят в число 14. После ошибочной цены запись совпадает с прежней; после отказа в удалении сохранён весь список товаров категории. [Новый отчёт](defense/figures/product-testing/browser-report.json) и [снимки](defense/figures/product-testing/) относятся к временной базе. Шесть исторических сценариев большого каталога повторно не запускались.

При повторном прогоне pytest обнаружена ошибка изоляции test_app_initializes_database_and_preserves_it_on_restart: запуск проверял временную базу, а запросы использовали обычный SessionLocal. Для запросов добавлена подмена get_db на временную сессию. Дополнительно проверено чтение сохранённого товара через API после перезапуска. После исправления все 154 теста пройдены. Код приложения не менялся.

Для повторения основного сценария в первом терминале:

```bash
.venv/bin/python -m scripts.check_server
```

Во втором терминале, используя Python с установленным Playwright:

```bash
python scripts/browser_check.py --output /tmp/catalog-browser-report --chromium /usr/bin/chromium
```

Playwright и Chromium — дополнительные инструменты проверки; они не нужны для обычного запуска приложения и не входят в `requirements-dev.txt`. Укажите путь к установленному Chromium своей системы.

Тестовый сервер работает на порту 8001 с отдельной временной базой. Скрипт до изменения данных проверяет признак тестового сервера и пустой каталог. После штатной остановки временная база удаляется. Для повторного прогона сервер нужно запустить заново.

## Пределы результатов

Нагрузочная проверка, одновременное редактирование несколькими менеджерами, перенос на PostgreSQL и проверка других браузеров не выполнялись. Тесты подтверждают перечисленные сценарии и не доказывают отсутствие всех возможных ошибок.
