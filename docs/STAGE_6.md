# Этап 6. Веб-интерфейс

Реализован интерфейс управления каталогом на FastAPI и Jinja2. Главный адрес `/` перенаправляет на `/products`. Пользователь подтвердил запуск предыдущей версии на macOS и разрешил продолжать несколько этапов без отдельных подтверждений; новый интерфейс проверен в облачной Linux-среде с Chromium.

## Что можно делать

- Работать с товарами: список, карточка, создание, редактирование и подтверждённое удаление.
- Работать с категориями: список с числом товаров, создание, редактирование и удаление пустой категории.
- Искать название без учёта регистра, одновременно выбирать категорию, диапазон цены, наличие и порядок сортировки.
- Переходить по страницам по 10 товаров; параметры отбора сохраняются в ссылках.
- Видеть ошибки ввода и конфликты уникальности, сохраняя введённые значения.

У занятой категории вместо кнопки подтверждения показывается объяснение и ссылка на её товары. Сервер повторно проверяет ограничение при POST: ситуация могла измениться после открытия страницы. GET подтверждения ничего не удаляет. При отсутствии категорий форма товара предлагает сначала создать категорию.

## Ключевые файлы и устройство

| Файл | Назначение |
|---|---|
| `app/routers/pages.py` | Получает запросы страниц, разбирает формы, вызывает общие операции, выбирает шаблон |
| `app/web.py` | Настройка Jinja2, русские сообщения проверки, форматирование цены и UTC-дат |
| `app/templates/base.html` | Общие меню, шапка, подключение локальных CSS и JS |
| `app/templates/products/` | Список, карточка, форма и подтверждение удаления товара |
| `app/templates/categories/` | Список, форма и проверка удаления категории |
| `app/static/styles.css` | Сетка, таблицы, формы и адаптивное оформление |
| `app/static/app.js` | Отображение UTC-дат в часовом поясе браузера |
| `tests/test_pages.py` | Сценарии HTML, ошибки, экранирование и сохранение данных |

Страницы и JSON API используют функции из `app/catalog.py`, а также схемы из `app/schemas.py`. Отдельного набора правил для браузера нет. Исключение — перевод строковых HTML-полей `quantity` и `category_id` в целые числа до проверки строгой схемой. Дробная запись, экспонента, отрицательные и слишком большие значения не проходят. JSON API сохраняет строгий контракт.

Пример пути данных: POST `/products` → `ProductWrite` → `catalog.create_product()` → SQLite → перенаправление 303 на карточку. Браузер затем делает GET; обновление карточки не повторяет отправку формы. При ошибке форма возвращается со статусом 422 или 409. Идентификаторы адресов ограничены диапазоном SQLite, чтобы слишком большое число не приводило к ошибке сервера.

Пользовательский текст автоматически экранируется Jinja2. Он не вставляется через `innerHTML` и не помечается безопасным HTML. API возвращает ошибки JSON, страницы — HTML. Основные операции не требуют JavaScript. Локальные стили и скрипт работают без CDN; Swagger по-прежнему использует CDN.

## Маршруты

| Адрес | GET | POST |
|---|---|---|
| `/products` | Список и фильтры | Создание |
| `/products/new` | Форма создания | — |
| `/products/{id}` | Карточка | — |
| `/products/{id}/edit` | Форма редактирования | Сохранение |
| `/products/{id}/delete` | Подтверждение | Удаление |
| `/categories` | Список и число товаров | Создание |
| `/categories/new` | Форма создания | — |
| `/categories/{id}/edit` | Форма редактирования | Сохранение |
| `/categories/{id}/delete` | Подтверждение или объяснение запрета | Удаление пустой категории |

HTML-маршруты скрыты из OpenAPI, чтобы `/docs` оставался документацией JSON API.

## Проверка и материал для главы 3.2

Браузерный прогон выполнил 14 сценариев с настоящим Chromium на отдельной временной базе. Проверены экраны 1440 × 1000 и 390 × 844, создание, изменение, фильтрация, пагинация, ошибки, запрет удаления занятой категории, отмена и подтверждение удаления, работа без JavaScript. Девять реальных снимков и описание их происхождения находятся в [figures/README.md](figures/README.md). Их можно использовать в главе 3.2 после оформления подписей по методическим требованиям.

Обнаруженное переполнение мобильной страницы устранено: скрытая служебная подпись таблицы теперь позиционируется внутри прокручиваемого контейнера. Прокручивается сама широкая таблица; вся страница остаётся в пределах экрана. Исправлено и выравнивание последнего столбца таблицы. Итоговый протокол приведён в [STAGE_7.md](STAGE_7.md).

На Mac: остановить сервер Control+C, выполнить `git pull --ff-only`, снова запустить командой из README и открыть главную страницу. Зависимости для интерфейса уже были установлены на предыдущих этапах.
