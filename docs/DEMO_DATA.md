# Демонстрационный каталог

Набор состоит из **1200 товаров в 12 категориях**, по 100 товаров на категорию. Это синтетические канцелярские товары без реальных брендов: цены и остатки условные, что отмечено в описаниях. Артикулы имеют вид `DEMO-01-01-01` и остаются одинаковыми при каждом запуске.

## Загрузка на своём Mac

В папке проекта с активированным окружением:

```bash
git pull --ff-only
source .venv/bin/activate
python -m scripts.seed_demo
```

Обычный сервер можно оставить работающим: после загрузки обновите страницу товаров. На пустой базе появятся 12 категорий и 1200 товаров. Если свои записи уже есть, они сохранятся; общие числа могут быть больше.

Исходник набора — [app/demo_data.py](../app/demo_data.py), команда — [scripts/seed_demo.py](../scripts/seed_demo.py). Данные не добавляются автоматически при старте приложения. Сам файл рабочей SQLite-базы в GitHub не отправляется: команда воспроизводит набор отдельно на каждом компьютере.

## Повторный запуск и резервная копия

- Перед записью в существующую базу создаётся `data/backups/catalog-before-demo-<UTC-дата>-<идентификатор>.db`. Путь выводится в результате команды.
- Используется SQLite backup API, которое учитывает зафиксированные данные журнала WAL. Ошибка копирования останавливает загрузку до изменения базы.
- Существующие артикулы пропускаются. Изменённые пользователем название, цена и остаток не возвращаются к исходным значениям. Повторная загрузка полного набора сообщает `products_added: 0`, `products_skipped: 1200`.
- Существующая категория с таким же нормализованным названием используется без перезаписи её описания.
- Вся загрузка выполняется одной транзакцией. При ошибке новые товары и категории откатываются.
- Если самостоятельно удалить демонстрационный товар или изменить его артикул, следующий запуск вновь добавит запись с отсутствующим исходным артикулом.

Для отдельного демонстрационного файла можно явно указать путь:

```bash
python -m scripts.seed_demo --database /tmp/catalog-demo.db
```

Обычное приложение продолжит использовать свою `data/catalog.db`; этот параметр меняет только место загрузки указанной команды.

## Фактическая проверка 21.10.2026

При проверке 21.10.2026 в рабочую базу загружен демонстрационный набор. До загрузки она была пустой; сделана резервная копия. Повторная загрузка добавила 0 товаров. `PRAGMA integrity_check` вернул `ok`, `foreign_key_check` — пустой список.

Полный pytest-прогон: **154 passed, 1 warning** (35 БД + 81 API + 31 HTML + 7 загрузчик). Новые проверки охватывают сохранение пользовательских данных, повторный запуск, конфликт артикула, откат всей загрузки, резервную копию с WAL и отказ при невозможности копирования. Предупреждение Starlette о тестовом HTTPX осталось прежним.

В Chromium пройдены ещё 6 сценариев большого каталога: числа API, пагинация и последняя страница, совместные фильтры, счётчики категорий и мобильная ширина. В этих сценариях проверялось поведение каталога; скорость и предельная нагрузка не измерялись.
