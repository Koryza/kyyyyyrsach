# Состояние проекта и оставшиеся задачи

Обновлено 21.10.2026. Пользователь подтвердил, что обновлённое приложение работает на его Mac, и разрешил продолжение без согласования каждого этапа.

| Часть | Состояние и результат |
|---|---|
| Этапы 1–2: требования и проектирование | Изучены документы МФЮА, согласованы тема и объём функций; PLAN.md и DESIGN.md |
| Этапы 3–5: среда, база и API | Запуск, SQLite, ограничения и десять операций API |
| Этап 6: интерфейс | Страницы товаров и категорий, формы, карточки, фильтры, пагинация и адаптивное оформление |
| Этап 7: проверка | 154 pytest-теста: 35 БД + 81 API + 31 HTML + 7 загрузчик; одно известное предупреждение TestClient/HTTPX |
| Демонстрационные данные | В облачную базу добавлены 1200 товаров в 12 категориях; резервная копия, повторный запуск без дублей; на Mac выполняется команда загрузки |
| Браузер | 14 основных сценариев интерфейса и 6 дополнительных на большом наборе; реальные снимки |
| Этап 8: записка | Текст трёх глав, введение, заключение, 5 таблиц, оглавление, снимки, Word и PDF. Черновик: требуется завершение |
| Этап 9: защита | Подготовлены речь, демонстрация, вопросы, PPTX/PDF на 8 слайдов и заметки докладчика. Репетиция и защита ещё не проведены |

Согласованная программная функциональность реализована. Облачный сервер использует `data/catalog.db`; файл и резервные копии исключены из Git. В GitHub находятся исходник набора и загрузчик, поэтому свой каталог на Mac наполняется отдельно:

```bash
git pull --ff-only
source .venv/bin/activate
python -m scripts.seed_demo
```

При уже созданных пользовательских данных команда добавляет недостающие демонстрационные записи, сохраняя имеющиеся. На пустой базе получится ровно 1200 товаров; со своими товарами общее количество будет больше.

## Что обязательно осталось до сдачи

1. **Заполнить реквизиты.** Кафедра, дисциплина, направление и профиль, ФИО, курс, группа, руководитель, город и срок. Неизвестное пока отмечено в Word и презентации. Формальное задание и отзыв заполняются по шаблонам с действительными данными; подписи и утверждения остаются участникам.
2. **Закончить научную библиографию.** Сейчас прочитаны и проверены 6 технических первоисточников. Новая методичка требует не менее 15 источников, рекомендации об антиплагиате ориентируют на 15–20 научных. Нужно подобрать и изучить научные публикации, а не просто увеличить число веб-ссылок. Затем оформить записи по ГОСТ и заменить временные `[T1]`–`[T6]` сквозными ссылками.
3. **Доработать текст и объём.** Сейчас PDF содержит 23 страницы вместе со служебными листами и четырьмя страницами приложения. До нормы 25–30 страниц без приложений работа не доведена. Нужно развить теоретический анализ по изученной литературе, введение до 1,5–2 страниц и заключение примерно до двух страниц, включить схемы из DESIGN.md, уточнить выводы и убрать служебную отметку.
4. **Проверить окончательное оформление.** Титул и задание, оглавление и номера страниц после редактирования, ссылки на таблицы и рисунки, подписи и приложения, финальный список литературы. Базовые параметры Word установлены; окончательная проверка проводится после дополнения документа. Неоднозначности методички уже записаны в PLAN.md.
5. **Проверить собственное понимание и отрепетировать защиту.** Пройти сценарий DEFENSE.md на своём Mac, объяснить путь запроса, цену в копейках, нормализацию поиска, внешний ключ и rollback. Заполнить титульный слайд, узнать длительность выступления и отрепетировать с таймером. Данные уже можно загрузить одной командой.
6. **Пройти академическую проверку в МФЮА.** Согласовать допустимый характер помощи ИИ, загрузить окончательную работу по правилам вуза, изучить полный отчёт оригинальности и устранить замечания. Документ об антиплагиате указывает порог 60%, но результат системы и решение преподавателя не получены и не обещаются.

Отчёт оригинальности, подписи, оценка и состоявшаяся защита не создаются как фиктивные файлы. Технические файлы готовы для дальнейшей содержательной доработки.
