# Этап 5. Серверные операции каталога и API

Реализованы создание, получение, изменение и удаление товаров и категорий, поиск, совместная фильтрация, сортировка и пагинация. Все операции доступны через JSON API и документацию FastAPI. HTML-страницы и формы будут добавлены на этапе 6.

## Как проходит запрос

Pydantic проверяет JSON или параметры поиска. Маршрут передает проверенные данные общей функции каталога. Функция проверяет наличие связанных записей и бизнес-ограничения, выполняет операции SQLAlchemy и фиксирует транзакцию. Маршрут формирует публичный ответ.

Например, POST товара проверяет формат цены и остатка, затем существование категории и уникальность артикула. После сохранения возвращается товар с идентификатором и кодом 201. При конфликте записи транзакция откатывается. Известные ошибки UNIQUE и внешнего ключа переводятся в понятный ответ 409; неожиданные ошибки базы не маскируются как дубликат.

Слой `catalog.py` не создает HTTP-ответы: он возвращает модели или поднимает `CatalogError`. Сейчас JSON-обработчик переводит эту ошибку в код и сообщение; на следующем этапе страницы смогут отобразить то же правило в форме.

## Маршруты

| Метод | Адрес | Назначение | Успех |
|---|---|---|---|
| GET | `/api/categories` | Список категорий по нормализованному названию | 200 |
| POST | `/api/categories` | Создать категорию | 201 |
| GET | `/api/categories/{category_id}` | Получить категорию | 200 |
| PUT | `/api/categories/{category_id}` | Изменить категорию | 200 |
| DELETE | `/api/categories/{category_id}` | Удалить пустую категорию | 204 |
| GET | `/api/products` | Список товаров с условиями отбора | 200 |
| POST | `/api/products` | Создать товар | 201 |
| GET | `/api/products/{product_id}` | Получить товар | 200 |
| PUT | `/api/products/{product_id}` | Заменить редактируемые данные товара | 200 |
| DELETE | `/api/products/{product_id}` | Удалить товар | 204 |

Ответ 204 не содержит JSON и тела. PUT требует все обязательные редактируемые поля; необязательное описание при отсутствии очищается. PATCH не реализован. GET-запросы не изменяют данные.

## Примеры входных данных

Создание категории:

```json
{"name": "Письменные принадлежности", "description": "Ручки и карандаши"}
```

Создание товара:

```json
{
  "name": "Ручка синяя",
  "sku": "PEN-001",
  "description": "Учебный демонстрационный товар",
  "category_id": 1,
  "price": "49.90",
  "quantity": 20
}
```

Вместо `1` необходимо подставить идентификатор, реально полученный при создании категории. Это пример запроса, а не сведения действующего магазина.

Цена передается строкой в рублях: `"49.90"`, `"49,90"`, `"49"`. Возвращается строкой с двумя знаками, например `"49.00"`. JSON-числа для цены не принимаются, чтобы не зависеть от преобразования дробных чисел в float. Более двух дробных знаков, отрицательная цена, NaN, Infinity, экспоненциальная запись и переполнение отвергаются. Внутри базы по-прежнему используются целые копейки. Нулевая цена допустима.

Количество и идентификатор категории передаются JSON-целыми числами. Строка `"1"`, логическое `true` и дробное `1.0` не заменяют целое число. Количество может быть нулевым. Идентификаторы должны быть положительными и помещаться в целый тип SQLite.

Артикул приводится к верхнему регистру. Обязательные названия не могут состоять из пробелов. Описание необязательно. Неизвестные поля, включая `id`, `price_kopecks`, `name_normalized` и даты, отвергаются с 422: ими управляет приложение.

## Ответы и отбор товаров

Список категорий возвращается массивом. Список товаров имеет поля `items`, `total`, `page`, `page_size`. Размер страницы — 10. Для пустой страницы массив пустой, но общее число найденных товаров сохраняется.

Товар в публичном ответе содержит идентификатор, название, артикул, описание, идентификатор и название категории, цену в рублях, остаток и даты. Внутренние поисковые поля и цена в копейках не выдаются. Даты явно обозначены как UTC с суффиксом `Z`.

Параметры GET `/api/products`:

| Параметр | Действие |
|---|---|
| `q` | Часть названия, без учета регистра, включая русский текст |
| `category_id` | Товары существующей категории |
| `min_price`, `max_price` | Включительные границы цены в рублях |
| `in_stock=true` | Только товары с остатком больше нуля |
| `sort` | `name_asc`, `name_desc`, `price_asc`, `price_desc`, `updated_desc` |
| `page` | Номер страницы от 1; по умолчанию 1 |

Все условия можно сочетать. Нижняя цена не может превышать верхнюю. Пустые необязательные границы и категория игнорируются. По умолчанию выдача сортируется по нормализованному названию; равные значения дополнительно упорядочиваются по идентификатору. Это сохраняет стабильность страниц.

Символы `%`, `_` и `/` в поиске воспринимаются буквально. Значения передаются параметрами SQLAlchemy, а сортировка выбирается из фиксированного списка. Неизвестные параметры и неверные значения возвращают 422; отсутствующая выбранная категория — 404. Пагинация ограничивает номер страницы так, чтобы смещение помещалось в целое SQLite.

## Ошибки

- 404: товар или категория не найдены.
- 409: повторное название категории, повторный артикул или попытка удалить категорию с товарами.
- 422: неправильный тип, пустое обязательное поле, неверная цена, остаток, фильтр или лишнее поле.

Ошибки каталога имеют вид `{"detail":"Категория не найдена"}`. Ошибки проверки данных используют стандартный ответ FastAPI со списком проблемных полей. При отказе в изменении исходная запись сохраняется. Переименование категории сохраняет связи товаров; перенос товара в другую категорию изменяет связь, не создавая копию товара.

## Проверка на своем Mac

Остановите старый сервер сочетанием Control+C. Из корня проекта с уже настроенным окружением:

```bash
git pull --ff-only
source .venv/bin/activate
python -m pytest -q
python -m uvicorn app.main:app --reload
```

Если окружение еще не настроено, сначала выполните команды [README](../README.md).

В браузере введите `http://127.0.0.1:8000/docs`:

1. В POST `/api/categories` нажмите Try it out, введите пример категории и выполните запрос. Запишите полученный `id`; ожидается 201.
2. В POST `/api/products` вставьте пример товара, подставив этот идентификатор. Ожидается 201 и цена `"49.90"`.
3. В GET `/api/products` задайте `q=РУЧКА`, категорию и `in_stock=true`. Ожидается товар в `items` и код 200.
4. Попробуйте удалить занятую категорию через DELETE: ожидается 409, товар должен остаться.
5. В PUT товара передайте все обязательные поля с новой ценой и остатком; проверьте изменения через GET.
6. Удалите демонстрационный товар, затем его пустую категорию. Ожидаются ответы 204.

В своем каталоге используйте отдельные демонстрационные записи, не удаляя существующие товары для проверки. Автоматические тесты сами создают и удаляют временные базы.
